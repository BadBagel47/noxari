# Noxari development guidance

## Handover and user workflow

Read `HANDOVER.md` at the start of a new session alongside this file and `README.md`. It records user decisions, current status, pending approval and the Guided Finder, the full-viewport workspace and current approval state. Recommend a model before each new development step and wait for the user's explicit approval; allow them to bundle changes before a run. Do not treat a roadmap entry as approval to implement it.

Keep `HANDOVER.md` current after each completed development step, relevant fix, user validation or change of plans/workflow. Record the verified app commit, test/deployment evidence, limitations, remaining work and approval state. Keep README and this file consistent; do not store secrets, private coordinates or full chat logs in the handover.

User priority after the fullscreen step: defer further UI refinement until the functional scope is complete. Prioritize remaining functionality; keep necessary functional controls and bug fixes within their approved step. The full 110-object Messier catalog was subsequently approved and implemented. Fixed objects now use shared J2000-to-horizontal transforms without DefineStar slots. No further development step is approved. Preserve source citations, explicit missing V/distance values and the M24/M40/M73/M102 special-case notes. Regenerate data with scripts/generate_messier.py; see src/generated/README.md and data/README.md for pinned sources and licenses. Do not alter source pins or reinterpret M102 silently.

This repository contains a **partly calculated prototype**, not a complete planetarium. The default eye-level view is a swipeable, optionally phone-synchronized 90° perspective of HYG stars and above-horizon object markers for the selected time and place. A zenith-centered all-sky map remains available. Both views use the same calculated horizontal directions. The ground is a generic geometric horizon, not local terrain. Star brightness is stylized, first-order proper motion is applied to the HYG stars and Sirius marker/curves, 88 schematic constellation figures and a separate optional official IAU boundary layer are available, and constellation altitude curves remain demos. Preserve demo labels for those curves.

Stack: React, TypeScript, Vite. Deploy via GitHub Actions to GitHub Pages at `/noxari/`. Preserve query-string object deep links (`?object=m31`).

User-approved priority order: (1) manual 360° eye-level sky view (implemented), (2) phone geolocation plus device-orientation synchronization (implemented; user confirmed Android/Brave following, broader compass validation remains), (3) proper motion and constellation figures (implemented), (4) all seven other planets with real positions, geocentric photometry and solar separation (implemented), (5) explicit heuristic Tonight suggestions and sunset/sunrise chart windows (implemented; no measured observing-quality forecast). Live-camera overlay is lower priority. GPS determines location; compass/gyro sensors determine the phone's orientation. Existing catalog objects have calculated altitude curves; Orion and Ursa Major retain demo curves because a whole constellation has no unique center.

Mobile-first, dark sky-first UI; English interface with optional Swedish astronomical names. Prefer open datasets with verified licenses. Never present demo visibility as real calculations.

Phone sensors are opt-in and require HTTPS. Relative orientation must be aligned to true north; absolute compass data can still use magnetic north, with no declination correction. Keep manual fallback, permission/error states, listener cleanup and the distinction between simulated browser tests and physical-device validation.

Planet markers are allowed during civil twilight (geometric Sun below 0°); deep-sky markers require Sun below −6°. A marker is not a promise of observability. Solar-system details use geocentric distance, modeled magnitude, phase and solar separation; altitude/azimuth are topocentric. Charts follow standard sunset/sunrise with 30-minute margins and at-most-10-minute samples; polar/partial nights use local noon-to-noon. Chart peaks use per-object darkness thresholds. Tonight suggestions additionally require altitude ≥10° (diffuse ≥15°), planets ≥15° from Sun, and future slots only. Diffuse targets are penalized by Moon phase, altitude and separation. Equipment filters suggestions; demo constellations are excluded. Keep reasons, thresholds and approximate-time labels visible. No weather, skyglow, aperture or observing-success prediction is modeled. Independent NASA/JPL reference fixtures run offline in tests/planets.test.ts.

Guided Finder now overlays the horizon view for individual calculated objects. Centering uses great-circle error ≤3° and must never be true below the horizon. The manual-center action pauses phone following and is labeled as simulated view alignment. No sensor permission is requested automatically on entry. Preserve the Android/Brave sensor-source fix. Next geometric rise is an approximate 48-hour/30-minute-bracket search. The full-screen workspace is implemented. Any next development step needs a fresh user approval.

The full-viewport workspace is implemented: keep the sky mounted across foreground panel changes. Panel state, selected preview object and guidance target are distinct. Exactly one sheet may be open. Panels pause view publication while the active sensor session retains its north reference; Resume is explicit. End session/Stop, hidden page or data timeout release sensors. Do not reset the tracker on panel opening/closing. Live Now ticks every 30 seconds, fixed time freezes; share the night context by window key so phone motions do not trigger night recalculation. More → About & sources contains visible attribution. Projection uses a 90° longer-axis field of view. Keep viewport/safe-area/keyboard sizing and keyboard focus/close behavior intact.

Official IAU boundaries: use the 781 unique B1875 edges in src/generated/boundaries.ts, not figure connectivity or straight J2000 chords. Preserve increasing RA across 24h, polar parallels and separate Ser1/Ser2 region IDs. src/constellationBoundaries.ts samples in B1875, converts with Astronomy Engine’s own B1875 convention to J2000 and then to horizontal coordinates, without proper motion. Cache by time/location; do not recalculate on phone movement. Clip at horizon/camera/viewport. Boundaries have an independent toggle, off by default; preserve source/license links under About & sources. Generator/source pins and approximation limits are in src/generated/README.md. The user approved and completed this boundary step after the Messier step; deeper stars, zoom and UI refinement need separate approval.
