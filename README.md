# Noxari — React + TypeScript prototype

A mobile-first planetarium prototype with a full-viewport calculated sky, swipeable eye-level and all-sky views, foreground panels, object positions and altitude curves.

For a new chat or project handover, read [HANDOVER.md](HANDOVER.md) together with [AGENTS.md](AGENTS.md). The handover is maintained as work and plans change and records the user's model-recommendation and approval workflow.

## Start locally

Requires Node.js 20.19+ or 22.12+ and npm.

```bash
npm ci
npm run dev
```

Open the local address printed by Vite (normally http://localhost:5173). For a production build:

```bash
npm run build
npm test
npm run preview
```

To test on a phone on the same Wi-Fi network, use the `Network` URL printed by Vite (your firewall may need to allow it).

## Included

- **Workspace** — a persistent sky filling the available browser viewport, with Search, Tonight, Follow/Stop and More quick actions. Mobile uses a bottom dock and bottom sheets; desktop/landscape uses a side rail and side sheets. Exactly one sheet opens at a time, with its own scrolling, focus containment and Escape/close support. Time/location and sensor status stay visible. Compact object selection offers Guide, Details and Save. More contains Saved, Sky display, Time & location, Phone direction, Settings and About & sources. Native fullscreen is optional where supported.
- **Look around** — the default eye-level perspective (90° on the longer viewport axis at 1×) of 4,105 HYG stars to magnitude 5.8 plus five fainter constellation endpoints, with proper motion from epoch J2000. Drag or swipe to turn a full 360° and look up, pinch to zoom from 1× to 3×, use the arrow keys, or open manual direction buttons under More → Sky display. A drag can start on an object marker or its label; a stationary tap selects it. Movement must exceed an 8 px threshold before panning starts, so small tap jitter does not move the sky. A two-finger pinch does not select a marker. Follow enables orientation sensors after a user gesture and permission where required; phone following remains active while the view is zoomed. An absolute compass reference is used when available; otherwise the user must point toward true north and align before following starts. The flat ground and level line mark the geometric horizon, not the local landscape. You can look down to nearly −90° with drag, keys, manual buttons or phone direction. Ground is solid at/above level and fades smoothly to transparent by −25°, revealing a clearly labeled simulated sky below the horizon. Guided Finder and observing suggestions retain their above-horizon requirements.
- **Constellations** — optional schematic line figures with independent Latin-name labels. **Common (24)** is the default; **All (88)** is available under More → Sky display. The selection is shared by both views and retained across panels for the session (reload resets it). Common is Noxari’s editorial selection, including southern landmarks, not an official IAU popularity category. Lines follow their stars and clip at the horizon. These figures are drawing conventions. A separate **IAU constellation boundaries** toggle under More → Sky display adds dashed purple area boundaries in both views, independently of the figures. It is off by default; both layers fade in daylight. The boundary network always includes all 88 constellations and the two separate Serpens regions, independently of the figure selection.
- **Milky Way** — an optional, initially enabled background in both views, aligned to the selected time and location. Five sourced contour levels provide a diffuse band and dark structures. Color/brightness are illustrative; daylight fades the layer out. More → Sky display contains its independent toggle, and About & sources links its credits and BSD license.
- **Sky map** — a switchable zenith-centered, azimuthal equidistant projection of the same stars, zoomable from 1× to 2.5× by two-finger pinch. Its outer circle is the geometric horizon; north is up. Both views share calculated above-horizon positions for catalog objects, the Moon, all seven other planets (Mercury through Neptune), and the Sun. Stars fade in daylight. Planet markers appear when the geometric Sun is below 0°; deep-sky markers require the Sun below −6°. The Sun and Moon remain available. Markers indicate calculated positions rather than guaranteed naked-eye visibility; Uranus and Neptune have optical-equipment guidance.
- **Observation controls** — Time & location opens from the top status chip or More. The default Now mode advances every 30 seconds and refreshes on return to the page. Manually changing the date/time enters a clearly labeled Selected time mode; Now returns to the live clock. Selected date/time and preset or manual latitude/longitude with an IANA timezone. Use my location requests a single browser geolocation fix and shows reported accuracy. It uses the device timezone, which can be changed manually; coordinates do not determine the timezone automatically. Times and night curves use the selected observation timezone, including daylight saving changes; coordinates are stored locally in the browser.
- **Tonight** — suggested objects ranked by an explicit altitude/darkness/moonlight heuristic, with approximate best times and contiguous favorable intervals after the selected time. Equipment filters the recommendations. Targets outside the criteria have explanations; constellation demo curves are excluded. The chart window follows standard sunset/sunrise with 30-minute margins, with noon-to-noon fallbacks for polar/partial nights. Shading distinguishes astronomical, nautical and civil twilight. All cards share the same night window.
- **Messier catalog / Explore** — all 110 Messier objects with calculated centers and night curves, search by English/Swedish name, exact M/NGC/IC identifier, subtype or constellation, category filters, saving and Guided Finder. Padded/spaced identifiers such as M001 and NGC 224 are accepted. M24 (star cloud), M40 (star pair), M73 (asterism) and disputed M102 have explicit notes. Per-object data-source links are available in Details. A zodiac constellation name reference remains separate.
- **Saved** — bookmarked objects, persisted in localStorage.
- **Object details** — descriptions, catalog information, altitude/azimuth at the selected time and an enlarged visibility chart. Solar-system objects also show geocentric distance, modeled visual magnitude, illuminated disk fraction, angular separation from the Sun and constellation for that time.
- **Sharing** — URL query links such as `?object=m31` (works when deployed; uses Web Share API or clipboard where supported).
- **Guided Finder** — select a calculated object and choose Guide from its compact card, or Guided Finder in its details, to open an overlay on Look around. A fine central ring carries an arrowhead around its edge toward the target; it turns green when the calculated direction is within 3°. The target ring and guidance stay aligned while zooming. Phone-following and north calibration remain opt-in. Drag and keys are manual fallbacks; Center manual view is in the target’s Details or Sky display panel. Below-horizon targets are never marked centered and show an approximate next geometric rise when found in the next 48 hours. Whole-constellation demo cards have no unique target and cannot start guidance.
- **Language** — EN/SV toggle; Swedish object names and selected UI copy.

## Sky interaction and readability

Object markers have transparent backgrounds, at least 44×44 px hit targets, readable labels and circular press/keyboard-focus feedback on the marker itself. Touch highlight rectangles are disabled for these markers; keyboard selection still works with Enter/Space. Dragging a marker does not open its object card. Capture starts only after the movement threshold; touch taps are explicitly activated on release to handle rapid tap-after-pan sequences, while a later compatibility click is suppressed. Cancellation and pointer release outside the sky clear the gesture. Finder controls remain ordinary buttons and do not start sky drags.

Each star-to-star line entering the viewport is drawn in and faded over 1,000 ms. In Look around, entry waits until the line reaches an inner area (12% inset, capped at 56 px horizontally / 80 px vertically), so a sliver at the screen edge does not consume the animation. The all-sky map reveals any visible line immediately. New lines animate independently of completed lines in the same figure. Animation state is kept across view-direction updates, with 180 ms tolerance for brief exits at an edge. Visible clipped line segments determine entry, including figures whose center is outside the screen. Render frames stop once the animation is complete. The operating system’s reduced-motion preference shows completed figures immediately and is observed live. Stars/figures remain attached to their calculated sky positions; the animation changes presentation only.

The Common selection is Andromeda, Aquila, Auriga, Boötes, Canis Major, Cancer, Carina, Cassiopeia, Centaurus, Crux, Cygnus, Gemini, Hercules, Leo, Lyra, Orion, Pegasus, Perseus, Scorpius, Sagittarius, Taurus, Ursa Major, Ursa Minor and Virgo. All source figures and the full IAU boundary network remain available.

The mobile readability pass increases descriptions to 16 px, most secondary panel copy to 14–15 px, sky object/star labels to 13 px and constellation names to 15 px. Controls retain touch targets of at least 44 px. Text spacing/contrast, wrapping statistics, scrolling sheets and landscape finder placement have been reviewed. Long time/location text is truncated within its status chip; tap it to read/edit the full observation settings. Labels can still overlap in dense sky fields; this is not a complete label-placement engine. Physical Android/Brave rendering and motion smoothness still benefit from user validation.

## Important scientific limitations

**The sky views show calculated directions, but are not navigation instruments.** The eye-level view uses a rectilinear field of view capped at 90° on the longer viewport axis and a generic level horizon. Star brightness and daylight fading are stylized. Both projections omit atmospheric refraction, terrain and light pollution. Lower-sky exploration reveals calculated positions through a fading geometric ground layer; these objects are physically blocked by Earth and remain unavailable to observing guidance. Sensor heading is undefined exactly at zenith/nadir; manual exploration reaches ±89.9° and valid sensor tilt is no longer limited to −80°. The star subset contains 4,105 stars to magnitude 5.8 and five fainter line endpoints (to magnitude 6.65). It applies first-order tangent-plane proper motion to J2000 coordinates, followed by the date/location rotation. This is an approximation for dates near the present, without radial velocity, perspective acceleration or annual parallax. The 88 constellation figures are schematic guides; the separate boundary layer draws the official IAU areas using sampled B1875 edges transformed for the selected time/place. It is a visual reference with sampled clipping and Astronomy Engine’s frame convention, not a sub-arcsecond astrometric reference. Orion and Ursa Major have no single catalog center, so their altitude curves remain marked as demos.

The Sun, Moon and all seven other planets are calculated with [Astronomy Engine](https://github.com/cosinekitty/astronomy) (MIT license). [Luxon](https://moment.github.io/luxon/) (MIT license) handles the observation timezone. All 110 Messier objects use fixed J2000/ICRS centers; Sirius uses its HYG center and proper motion for both the map marker and altitude charts; their current altitude and azimuth are calculated for the chosen coordinates and time. The mini and detail charts sample geometric altitude through the local night. Twilight shading uses the calculated solar altitude: astronomical darkness below −18° and twilight from −18° to −6°. Altitude curves omit atmospheric refraction, terrain, weather, light pollution and horizon obstructions. Standard sunrise/set times include the Sun’s upper limb and normal refraction, so these events differ slightly from the geometric solar-center horizon. Moon phase, height and angular separation influence the planning heuristic. “Highest” marks the highest sampled altitude with the object above the horizon and the Sun below the object’s darkness threshold; it can differ from the suggested time, which also weighs moonlight and excludes past slots. Solar-system distances, phases, Sun separations and constellation assignments refer to Earth’s center. Visual magnitudes are model estimates without atmospheric extinction, weather, equipment or local visibility corrections. Samples are spaced at most 10 minutes apart, so brief observing opportunities and exact optimal times can be missed; suggested times/ranges are explicitly approximate. The marker view accepts any selected time.

The star map uses an adapted subset of [HYG Database v4.1](https://github.com/astronexus/HYG-Database) by Astronexus contributors, under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). Its subset removes the Sun, selects stars to magnitude 5.8 plus five fainter constellation endpoints, rounds coordinates for compact delivery, and retains proper motions, HIP IDs and a few bright names. The generated dataset in `src/generated/brightStars.ts` is shared under the same license. Reproduce it with `python3 scripts/generate_bright_stars.py`; the script verifies the pinned source checksum before writing it. Attribution and license links remain accessible through More → About & sources in the app.

Constellation connectivity and Latin names are adapted from the [Stellarium modern skyculture](https://github.com/Stellarium/stellarium/tree/daace2add6a1bf886e8ee1934f51e9c69f818d18/skycultures/modern) by the Stellarium team, under CC BY-SA 4.0. We retain only the HIP line lists and names, and compute label centers from their member stars. No illustrations are embedded. The adapted `src/generated/constellations.ts` remains under the same license. The generator verifies both upstream checksums; see `src/generated/README.md` for provenance.

Official boundaries adapt 781 B1875 edges from that same pinned, CC BY-SA 4.0 Stellarium dataset, whose source credits Pierre Barbier’s edge table. Shared edges are drawn once. Sampling preserves constant-declination small circles and increasing RA across 24h, then converts B1875 → J2000 → horizontal coordinates; no stellar proper motion is applied to areas. Positions are cached by date/location, so phone movement only reprojects them. A separate generator verifies the data and license-description checksums: `python3 scripts/generate_boundaries.py`. Full provenance and sampling/frame limits are in [generated-data documentation](src/generated/README.md).

The Milky Way grid adapts José R. Vieira’s contour catalog from the pinned BSD 3-Clause distribution of d3-celestial by Olaf Frohn. A 23 kB local grayscale grid is sampled in J2000 coordinates from inverse screen rays, preserving the band’s time/location alignment and RA seam. Its brightness, tint and smoothing are visual choices, not measured observing quality. Exact source pins, licenses, rasterization and reproduction are in [generated-data documentation](src/generated/README.md). No remote image service is used.

The complete Messier dataset adapts [OpenNGC](https://github.com/mattiaverga/OpenNGC) by Mattia Verga (CC BY-SA 4.0), with pinned inputs, checksum verification and same-license distribution. Noxari authors the type groupings, descriptions, translations and broad equipment guidance. M102 follows NASA/Hubble’s adopted NGC 5866 identification rather than OpenNGC’s M101 duplicate association, with the dispute displayed explicitly. There are 102 source integrated V magnitudes; seven absent V values and M40’s unverified pair magnitude remain explicit, without substituting other bands. A separate cited [NASA/Hubble factual snapshot](data/README.md) provides 88 approximate distances. The remaining 22 entries show missing data or no assigned common distance (M24/M40/M73). These estimates replace the previous five Messier distance examples; they are not precision measurements. See [generated-data provenance](src/generated/README.md) for source pins, adaptations and reproduction.

Fixed-source coordinates use one shared J2000-to-horizontal rotation per time/location, including precession and nutation. They omit annual aberration and parallax, consistently with the star field; distances are metadata rather than astrometry inputs. There is no eight-object DefineStar slot limit. Night curves share transforms across the catalog, and view movement reprojects cached current positions instead of recomputing object ephemerides. Sirius retains HYG proper motion; planet calculations are unchanged. The initial view defaults to Stockholm until a user selects another location. Geolocation is requested only by Use my location; coordinates are stored only in this browser.

The app does not embed astronomical photos; the Milky Way PNG encodes a contour-derived brightness grid. Before adding per-object imagery, verify its license and show its source and attribution.

## Phone location and direction

Open the HTTPS site on your phone, tap the top time/location chip and **Use my location**, close the panel, then choose **Follow** in the quick dock. Allow the requested permissions and hold the phone upright with the screen facing you. Use **Now** for the current sky, or keep a selected time to explore another date. Point the back of the phone toward a known **true north** direction and open the sensor-status chip and tap **Align north** if asked, or if the compass drifts. Following stays enabled through search, selection and editing panels until Stop is pressed. The browser's compass may report magnetic north; magnetic declination is not modeled. Stay away from metal and magnetic cases. Compass accuracy varies by device. The user has confirmed that following and the compass-settling correction work on Android with Brave; broader outdoor alignment and iOS validation remain.

On Android, regular orientation drives motion while absolute compass readings remain an independent reference check when a separate usable stream exists. Automatic north anchoring waits for fresh stationary readings instead of pairing values from different phone poses. For compass-based references, a stable large disagreement (≥20° for 1.5 seconds after stationary histories settle) now reanchors once to the compass, with a visible notice and at least ten seconds between automatic corrections. Small compass settling leaves the relative offset unchanged. Manual true-north references are preserved; source/frame changes and cases without reliable comparison retain **Check north** and explicit recovery. In Phone direction, **Use compass reference** reanchors from fresh stable data; **Align north** remains the true-north fallback. Automatic recovery also applies while a panel is open. Switching to the all-sky map retains the session and uses the latest pose on return. If only one usable stream is available, the panel explains that no independent comparison is possible. Agreement between sensors is not measured pointing accuracy. Full thresholds, source limitations and physical test instructions are in [DIRECTION_STABILITY.md](docs/DIRECTION_STABILITY.md).

The view follows the back-screen direction with a level horizon; screen roll is not rendered. Readings directly upward/downward have no usable heading. Permission denial, unsupported APIs and missing readings leave manual control available. Search, object selection, panel changes and closing Guided Finder preserve following. The all-sky map retains the sensor session; returning to Look around immediately uses the latest fresh pose. Manual pan, direction buttons and manual centering require Stop first, so they do not compete with active following. Sensor uncertainty still holds the view until recovery is possible. Explicit Stop, missing sensor data or hiding the page ends the session; a fresh start may need north alignment again. A pending permission request survives panel opening; Stop and hiding the page cancel it. No location watch, sensor access on load or camera access is used. Direction reports are downloaded locally on request and retain recent readings plus bounded frozen windows and timestamped transitions around warnings/reanchoring, without GPS coordinates; they are not uploaded automatically. Browser-level GPS, permission and orientation flows have been checked with simulated inputs; this does not verify real compass accuracy.

## Guided Finder

Open an individual object’s details and choose **Guided Finder**. The app switches to Look around and focuses the persistent sky; it keeps the selected date, time and location, shown in the target header. Enable **Follow** using the quick dock and calibrate north in the Phone direction panel if needed, or turn/tilt the manual view. Starting the finder does not request sensors or location automatically. **Center manual view** (in Details or Sky display) requires Stop first and points the simulated view at the target; it does not demonstrate physical phone alignment. **Details** opens a panel while retaining following and the guidance target. Other panels and map selection also retain the target. Escape closes the top panel first; Escape in the sky exits guidance. Exiting guidance returns to the compact object card.

Horizontal turn is the shortest signed azimuth difference; tilt is the altitude difference. Angular distance and the 3° centered test use great-circle separation, so near-zenith targets work even if azimuths differ greatly. Centering means the calculated direction matches the view, not that the object has been visually detected. Compass drift, magnetic north, unrendered screen roll, atmospheric effects and the generic horizon still limit accuracy. A daylight target is explicitly marked as a calculated position. There is no camera overlay.

For a below-horizon target, a 30-minute-step search over the next 48 hours brackets upward geometric altitude crossings and refines the first detected one to approximately one minute. This omits refraction and can miss very brief grazing crossings; no crossing found is reported explicitly. These rise times differ from standard upper-limb/refraction sunrise/set times used to frame the night charts.

## Tonight planning model

The night is assigned within a local noon-to-next-noon interval using calendar arithmetic across DST. Standard sunset and sunrise are searched within that interval. Normal charts begin 30 minutes before sunset and end 30 minutes after sunrise. Before dawn the current night is retained; after the morning window ends, the next evening is selected. If no events occur, the chart uses the full noon-to-noon interval and identifies polar day/night. Single/reversed crossings (including unusual manually paired longitude/timezone combinations) use a labeled partial-night fallback.

`nightContext` computes shared Sun/Moon samples at no more than 10-minute spacing. Bright planets and the Moon require Sun below −1°, stars below −6°, diffuse targets and Uranus/Neptune below −12°. Recommendations require altitude ≥10° (≥15° for galaxies, nebulae, clusters and star clouds); planets also require Sun separation ≥15°. Equipment is a minimum-class filter, not an aperture or sensitivity simulation. These are conservative planning choices, not visibility guarantees or safe-pointing instructions.

For diffuse objects, score = `0.65 × sin(altitude) + 0.35 × darkness − 0.4 × moonPenalty`, where darkness increases linearly from 0 at solar altitude −6° to 1 at −18°. Moon penalty is illuminated fraction × positive sine of Moon altitude × `(0.25 + 0.75 × (1 − targetMoonSeparation/180))`. Other targets use `0.8 × sin(altitude) + 0.2`. Only future samples relative to the selected time can be suggested. A favorable interval is the contiguous run around the best sample within 0.08 score units of its score. Scores are used to order suggestions and are not presented as probabilities. Weather, skyglow, surface brightness, lunar scattering, atmospheric extinction, instrument aperture and an observer’s eyesight are not simulated. Changing these weights would change the order; the interface explains the factors and exclusions.

Tests cover lunar interference, horizon/daylight constraints, inner-planet twilight, equipment and demo exclusions, past-slot filtering, disjoint intervals, DST and polar conditions. The algorithm has not been calibrated against measured observing success. Expanding to faint Messier objects does not validate their observability; equipment classes are broad Noxari guidance, and integrated magnitude is not used as a surface-brightness or detection model.

This project uses the existing `BadBagel47/noxari` repository. Push to `main` to run `.github/workflows/deploy.yml`, which installs from `package-lock.json`, runs the astronomy tests, builds, and deploys `dist/` through GitHub Actions. The repository's Pages source is GitHub Actions.
